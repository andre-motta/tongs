Released 2026-10-20. This patch release keeps the inbox current after you act
on a review, stops the terminal command palette from stacking screens or
throwing away text you typed, shows review threads on the unchanged lines you
expand, and leaves archived projects out of Reviews and My MRs. Most of it comes
from contributors, thank you all! Nothing in your configuration or drafts
changes.

## Install

```bash
pipx install tongs==1.1.1
```

`pip install tongs==1.1.1` and `uv tool install tongs==1.1.1` work the same
way. To upgrade an existing installation, run `pipx upgrade tongs`, or
`uv tool upgrade tongs`, or `pip install --upgrade tongs`. If you use the
per-user desktop app, install the matching desktop release after the core:

```bash
tongs desktop update
```

## The inbox

- **The inbox stays current after you act on a review.** Going back from an MR
  you merged, closed, approved or reviewed reloads the tab you came from, so
  it no longer lists the MR as it was. On All Open, a merged or closed MR's row
  is removed in place, so the pages you loaded and your cursor stay where they
  were. Going back without changing anything reloads nothing.
  ([#311](https://github.com/andre-motta/tongs/issues/311),
  [#458](https://github.com/andre-motta/tongs/pull/458))
- A repository refresh keeps the tab you are reading instead of jumping back
  to My Reviews.
  ([#311](https://github.com/andre-motta/tongs/issues/311),
  [#458](https://github.com/andre-motta/tongs/pull/458))
- **Archived projects leave Reviews and My MRs.** Archived GitLab projects and
  GitHub repositories are read-only, so their open merge requests and pull
  requests no longer fill these tabs. All Open still lists a cloned project
  that was later archived.
  ([#440](https://github.com/andre-motta/tongs/issues/440),
  [#463](https://github.com/andre-motta/tongs/pull/463))

Thanks to @rd4398 for #458, and to @HarshRajSinghania, whose change in #444
became #463.

## The command palette

- **Inbox and Repos no longer stack duplicate screens.** Choosing either from
  the command palette, or pressing ++r++ on the inbox, goes back to that screen
  if it is already open instead of opening another copy, so ++escape++ always
  leaves a screen. From a repository's inbox, palette **Inbox** reaches the
  main inbox.
  ([#311](https://github.com/andre-motta/tongs/issues/311),
  [#458](https://github.com/andre-motta/tongs/pull/458))
- **The palette keeps text you typed.** It refuses to leave, with a notice,
  while a review submission or draft change is running, while the comment
  editor holds text, or while the review submit dialog has an unsaved summary
  or verdict. These are the same checks ++escape++ applies. ++escape++ itself
  now also keeps a typed comment when the focus is outside the editor.
  ([#311](https://github.com/andre-motta/tongs/issues/311),
  [#458](https://github.com/andre-motta/tongs/pull/458))

## Diffs

- **Review threads show on expanded unchanged lines**, in the terminal's
  Unified and Split views and in the desktop app's unified diff. An expanded
  line with a thread shows the same marker as a changed line, dim when every
  thread on it is resolved. ++close-bracket++ and ++open-bracket++ in the
  terminal and ++n++ and ++p++ in the desktop app stop on it, and ++d++ in the
  terminal shows and hides the thread. Expanded lines stay read-only: you still
  cannot start a new comment on them. The desktop Split view follows later.
  ([#429](https://github.com/andre-motta/tongs/issues/429),
  [#459](https://github.com/andre-motta/tongs/pull/459))
- In the terminal's Unified view, an unchanged line inside a hunk that has a
  GitHub thread on one side now shows its thread marker, and the thread keeps
  it from folding away, as the Split view already did.
  ([#459](https://github.com/andre-motta/tongs/pull/459))

Thanks to @rd4398 for #459.
